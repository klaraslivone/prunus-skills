# Lessons from use

Format: what happened · lesson · where recorded

- The shareability requirement came after the design and forced a rework · ask "who is the skill for" in phase 0 · rule (phase 0)
- Research as a document with an approval stop caught the direction before files existed · always a research document plus a pause · rule (phase 2)
- A real-input test revealed an internal contradiction in the output (two parts disagreed) · check consistency across output parts during review · rule (skill-review)
- Users want verified facts distinguished from estimates · mark them in the research and in skill outputs · rule
- Users wanted skill files in English for sharing but output in their own language · files in English, output in the user's language, for this and every built skill · rule (Language)
- A built skill silently applied a non-obvious domain fact (output format required by a platform); the user only discovered why later on their own · flag non-obvious facts the design depends on · rule (Teaching, phase 2)
- Phase 4 reported only the outcome, so the user never learned to judge the output · hand over a yes/no reviewer card and let the user run the test with it · rule (phases 4–5)
- Self-review by the model that built the skill, plus an optional test, made unverified output look finished · end review with a "Not verified:" line, make the real test required or label the skill "untested" · rule (phases 4–5)
- The reviewer card asks about domain correctness, which a non-expert user cannot judge · state which items the user can't judge and how to cover them (named source, practitioner) · rule (phase 4)
- The description summarised the workflow, against the skill's own review rule · description says only when to trigger · rule (description)
- Research had no recency requirement, so "latest" was an assumption · date every source, prefer the last 12 months for fast-moving topics · rule (phase 2)
- A trigger test showed the skill rarely starts when a generic skill-creation skill is installed; the first eval run reported 0 triggers, a control skill proved the tool works · test the description in the real environment with a control, and say so in the README when it under-triggers · rule (launch)
